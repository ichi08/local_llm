# 現在の状態

最終更新：2026-10-03

## 現在の依頼と段階

利用者の依頼は、提案済みの改善を実装してPushし、`./setup.sh` → `./benchmark.sh` の流れで使える状態にすること。特にログ表示を人間に分かるものへ改め、独立レビューを行うこと。

実装と独立レビュー、54件の自動テスト、実機の全文入力・GPU／CPU起動・時間制限・中断・再開まで確認した。全モデルの性能・品質比較と運用用APIの常駐機能は未完了。Note公開の目的を評価課題へ混ぜない。

## 現在使える機能

- `setup.sh`：PC調査、専用 `.venv` 作成、ネイティブllama.cppの導入と依存dylibの固定。Python版・アーキテクチャ・runtime版と各ファイルSHA-256を記録する。activateは不要。
- `benchmark.sh`：setup環境を使い、入力取得、重みのサイズ・SHA検証と再利用／不足分取得、モデル切替、GPU／CPUの測定、結果保存を行う。
- ログは監視プロセスへ一本化。工程ごとの表示、取得量・割合・速度、課題・反復・デバイス・待ち時間、自然終了と失敗理由を日本語で表示する。TTYは1行更新、非TTYは節目と30秒heartbeat。
- 既定は英語のGoogle Argonページ全文をノイズ込みで渡す要約・翻訳・解説・自由創作各2問。各5回で基本280応答。生成数は上限なし、文脈長16,384、総時間300秒、接続15秒、無通信120秒。
- 実行前にモデルのテンプレートとtokenizerで全文入力の長さと実効文脈長を確認する。入力を黙って短縮しない。
- `.local/inputs/` へ取得結果を固定し、実行記録へ正確なプロンプト・HTML・全文・取得日時・方式・SHAをコピーする。`--plan` は取得や起動を行わない。
- `realistic_pages.json` に日本語記事・FAQ・技術文書と日→英全文翻訳、`conversation.json` に全文への要約→訂正→書き直しを追加。会話の履歴は毎回送信し、各ターンの集計を分ける。
- `setup.sh --browser` と入力のcapture_methodでJS実行後のDOMを取得可能。Chromium版と取得条件を記録する。既定はstatic HTML。
- 時間制限・通信切断・Ctrl+Cでも途中の本文・思考・timingsを保存する。再開は入力・重み・実行基盤・コード・設定の一致を要求し、未完了を新しいattemptとして追記する。
- 自然終了のみを各課題／ターン別に中央値・平均・標準偏差で集計する。失敗・打切り・未実行を分ける。品質は自動の客観的確認と人間の評価を分離する。
- HTMLレポート、answers、results、summary、人間の評価用JSON、起動時間、2秒ごとのRSS・システムswap・メモリ圧迫を保存する。

## 検証済みの範囲

- M1 Pro / CPU10コア / GPU16コア / RAM16GiB。llama.cpp 0.5.0 build11146 commit7fe450e19をネイティブ実行し、MiniCPM5-1B Q4_K_Mを検証済み重みから再利用。
- setup初回・再実行・ブラウザー追加、専用venvの優先、別の作業フォルダ、計画とhelp、シェル構文。
- 自動テスト54件。SSE、計測範囲、実ソケットでの厳密な締切、途中保存、入力超過、キャッシュ消去、再開条件、試行保持、会話履歴と集計、HTMLエスケープ、環境改変検知、ログの競合と件数を確認。
- 全文15,920文字の要約では入力3,596 tokens。実行基盤が報告するprompt_nと一致し、GPU25層／CPU0層を確認した。両方45秒の検証用総時間に達し、反復した途中本文を保存した。回答成功や速度比較の完成データとは扱わない。
- 全文の自由創作では入力3,605 tokens。時間制限時の途中思考を保存し、同条件再開で古い試行を残して新しい試行を追記した。
- 実Ctrl+CではGPUの途中思考を保存、CPUを未実行として記録、終了コード130と再開案内を確認。同条件再開ではGPU／CPUを再試行し、処理済み件数が総数を超えないことを確認した。
- 日本語記事7,543文字、FAQ885文字、技術文書4,797文字を取得し、各課題へ全文の末尾まで付くことを確認。
- 実ChromiumでJS追加文章・重複メニュー・ページ末尾の保存、HTMLレポートの表示・絞り込みを確認。
- 独立レビューで終了直前イベント欠落、中断案内、ダウンロードrename競合、再開エラー、再試行時の過剰カウントを修正し、再検証で残る重大な表示問題なし。

過去の短い入力・生成上限2,048でのGPU／CPU実測は旧条件であり、新しい全文・上限なしの結果と混ぜない。
