# プロジェクトのコンテキスト

## 目的

個人PCでローカルLLMを動かし、APIとして利用するための実験と運用調査を行う。
試行錯誤の根拠を残して記事化し、読者がAIと協働して同じ手順を再現できるようにする。

「PCで動くこと」「APIとして使えること」「自分の用途に十分な速度と回答品質があること」を順に検証する。
初回は所有者が作業を理解できるよう、PC調査から段階的に進める。

## セットアップの設計

入口は `setup.sh` とし、処理は次の段階へ分けて拡張する。

1. **調査**：ハードウェア、メモリ状態、空き容量、導入済みツールを取得する。
2. **ヒアリング**：用途、日本語の必要性、速度と回答品質の優先度、文脈長、同時利用数を確認する。
3. **選定**：候補モデル・量子化・必要容量・配布条件を示し、実行基盤を決める。
4. **導入**：依存関係と重みを用意し、取得元・revision・ハッシュを記録する。
5. **検証**：起動、短い応答、日本語の用途、文脈長、メモリと速度を確認する。
6. **API化**：ローカルAPIの起動・停止、疎通、クライアント利用を整備する。
7. **説明**：再起動後に使えるコマンドと利用例、実測した制約を説明する。

重みの取得済み判定と途中再開を設け、再実行で同じ重みを二重取得しない。
ヒアリング結果と実行設定は `.local/` に保存する設計とし、利用者ごとに再利用する。
今の `setup.sh` が実装しているのは段階1のみ。

## 実装の境界

- 実行基盤は未選定。Apple Silicon対応の候補を調査してから選ぶ。
- APIは既存の実行基盤が提供する機能を調べ、必要な部分だけを追加する。
- OpenAI互換のAPIを候補とし、具体的な対応範囲は選定後に確認する。
- モデルID、revision、量子化、ライセンス、コンテキスト長は設定として扱う。
- 個人用の設定・生成物・ログを `.local/`、重みを `models/` または基盤のキャッシュへ保存する。
- 依存は選定後に固定し、APIやベンチマーク用のディレクトリも必要になった段階で追加する。
- 初期のAPI接続先は `127.0.0.1` とし、同時利用はまず1件で検証する。
- macOSで手順を確立してから、Linuxなどの対応範囲を広げる。

## 記録の設計

`docs/state.md` に現在地と次の作業、`docs/research/` に条件付きの実測を残す。
実験ではコードのcommit、OS、実行基盤とバージョン、モデルとrevision、量子化、設定、プロンプトを固定する。
初回起動とウォーム状態を区別し、生成速度、最初のトークンまでの時間、メモリ、回答の評価を記録する。
品質は実際の応答と評価基準を根拠にし、モデルサイズだけで断定しない。
